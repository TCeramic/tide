## 可确认的 P2

### 1. 顶栏同时保留两个完全相同的首页入口

- 位置：`src/renderer/layers/library.ts:309`、`:333`、`:374`、`:606`。
- 触发：启动任意主题，观察搜索框左侧；独立 House 按钮后，折叠主导航中又有一个 House 按钮，两者均调用同一个首页导航。
- 证据：`artifacts/desktop-redesign-smoke/lens/light/900x650/library-local.png`、`lattice/dark/1600x1000/home.png` 可直接看到相邻两个首页图标。
- 影响：违背初稿 3.4“不允许主导航出现重复、含义相近且没有必要的入口”，也与用户后续删重复控件的方向冲突。窄窗口还占用可用搜索宽度。
- 建议：保留浮岛内首页；独立 home-mark 改为纯品牌标记或移除。若其作为明确降级导航保留，应仅在浮岛不可用时出现，而非同时占位。

### 2. 当前歌曲卡的状态标签永远是“此刻正在播放”

- 位置：`src/renderer/layers/home.ts:43`、`:119`。
- 触发：有歌曲时暂停，或启动恢复到暂停状态；标题仍写“此刻正在播放”，`setQueue` 仅更新歌名、歌手、封面，不读取 `snapshot.status` 更新状态。
- 证据：现有浏览器 fixture 初始 `status: paused`，首页截图仍显示此标签。
- 影响：初稿 4.2 A 要求准确、简洁的播放状态；在暂停/错误状态下 UI 给出相反信息。
- 建议：根据状态切换“继续聆听 / 正在播放 / 正在加载”等标签；没有歌曲时使用中性空态。不增设重复控制按钮。

### 3. 队列面板没有当前位置或进度表达

- 位置：`src/renderer/layers/library.ts:979`—`:1041`。
- 触发：歌曲播放到任意非零时间后打开队列；面板只显示数量、当前行颜色、歌名/歌手和操作按钮，无当前歌曲的已播放位置。
- 原因：`renderQueue` 的签名只包含 `[snapshot.index, snapshot.queue]`，且行结构没有时间/进度节点；`positionMs` 更新不会触发任何队列进度刷新。
- 影响：初稿 6.3 明确列出“当前播放位置”；当前选中行不等价于时间位置。如果“位置”原意只指队列序号，应在验收映射中说明，不能以存在 Dock 默认为面板该项已完成。
- 建议：在当前行或队列标题增加轻量当前时间/总时长；只更新一个文本节点，不重绘整个队列。

## 需要补证据或明确映射的项目（不是已确认运行故障）

1. **首页轻量当前歌词**：初稿 4.2 E 和最终验收要求当前原文/翻译及点击进入播放页。当前 `home.ts:113` 完全移除了歌词节点及 `tide:lyric-current` 订阅。用户要求删除重复卡片，允许把歌词放回当前歌曲元数据附近，不能据此自动推定其撤销了全部轻量歌词需求。建议在同一当前歌曲模块集成一行原文/译文，或在任务验收映射中明确这项后续决策。
2. **最小窗口**：主窗口最低为 800×560（`src/main/index.ts:98`），截图矩阵只测 900×650 和 1600×1000（`scripts/desktop-redesign-smoke.cjs:411`）。应补 800×560 下展开导航、搜索分类、设置全部分类及队列的边界/可点击性检查；现在不能把两种视口结论扩大为所有合法窗口尺寸。
3. **设置、菜单、长列表真实覆盖**：截图脚本仅对打开后的默认外观分类截图。现有 99 张图并未覆盖快捷键、桌面歌词、关于更新页、右键菜单、长歌单分页/拖拽、超过一屏历史记录的几何和交互。应补对应截图或明确限制。
4. **主题资源和长时性能**：初稿 8.3 / Phase 6 要求反复切换、最小化恢复、长时运行及资源无持续增长。当前有舞台生命周期单元测试和短时 Electron smoke，缺少两主题重复切换后的 context/texture/内存或长时趋势记录；不能将短时像素验证当作资源泄漏验收。
5. **历史持久恢复的覆盖深度**：代码和测试已证明 renderer reload 恢复及本地元数据持久化；脚本只在 Lens light 900 场景模拟两首后 reload。还应补应用进程重启、100 首上限、不同日期的排序和已移除本地文件点击后的错误反馈。此项是增强验证，不否定已经实现的跨会话持久化。

## 可达性补查

- 本地音乐空态可达：首页音乐库整卡 → 全部歌单页的“本地音乐”标签 → `showLocalLibrary()` → “添加本地音乐”。对应 `library.ts:439`—`:454`、`:867`—`:888`，不依赖已删除的小按钮。
- 每日推荐可达：`library.ts:666` 在全部歌单中保留 `tide-daily` 条目，`:679` 点击走既有 `dailyRecommend()`。因此不能认定删首页小按钮删除了每日推荐。
- **新增 P2：探索页加载成功后私人雷达/私人 FM 的稳定入口消失**。`navigate(explore)` 先 `showSheet(explore)` 展示推荐按钮（`:503`），随后的 `refreshToday(false)` → `showCatalog()`（`:795`）→ `showSheet(detail)` 又把推荐操作区隐藏。正常网络下用户进入探索等待加载完即触发；只有请求返回前短暂可见。每日推荐另有歌单条目兜底，雷达/FM 没有其他稳定 UI 入口。建议显示今日潮汐详情时保留推荐区，或统一纳入探索菜单。
- **队列键盘关闭风险**：`:396` 的 `delayQueue` 只检查 hover，不检查 `queueCol/queuePeek.contains(document.activeElement)`；从队列唤出区域 Tab 到按钮/队列条目会触发 focusout，约 240ms 后即便焦点仍在队列内也可能关面板。应补纯键盘复验，并用 focus-within 阻止自动关闭。
